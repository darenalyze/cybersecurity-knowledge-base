# IPv4 Issues

## The Need for IPv6

### Why IPv4 is Running Out
* **Address Limit:** IPv4 only has **4.3 billion** addresses. They are almost completely used up.
* **The Solution:** **IPv6** uses **128-bit** addresses, offering **340 undecillion** addresses.
* **Built-in Upgrades:** IPv6 includes **ICMPv6**, which automatically sets up IP addresses and resolves network locations.
* **Internet of Things (IoT):** Millions of smart devices (cars, sensors, home appliances) need their own IP address, forcing the move to IPv6.

### Why NAT is Not Enough
* **NAT Limits:** NAT helped save IPv4 addresses, but it causes slow connections (**latency**) and breaks **peer-to-peer** apps.

### EXAMPLE: Real-World IPv6 Usage
> * **Mobile Networks:** Over 90% of top US mobile traffic uses IPv6.
> * **ISPs & Sites:** Sites like YouTube, Facebook, and Netflix use IPv6. ISPs like Comcast (65%+) and Sky (86%+) have largely moved to IPv6.

## IPv4 and IPv6 Coexistence

IPv4 and IPv6 must run together during the transition. The **IETF** created 3 migration methods:

### 1. Dual Stack
* **How it works:** Devices run **both IPv4 and IPv6** at the same time on the same network.
* **Goal:** This is the **best and main method** (Native IPv6).

### 2. Tunneling
* **How it works:** Encapsulates (wraps) an **IPv6 packet inside an IPv4 packet**.
* **Goal:** Moves IPv6 data across IPv4-only networks.

### 3. Translation (NAT64)
* **How it works:** Converts **IPv6 packets to IPv4** (and IPv4 back to IPv6).
* **Goal:** Helps IPv6-only devices talk to IPv4-only devices.

### Quick Visual Summary
```
[ Dual Stack ]   --> Runs IPv4 and IPv6 side-by-side
[ Tunneling  ]   --> Wraps IPv6 inside IPv4
[ Translation]   --> Converts IPv6 <---> IPv4
```

security note: *When using Dual Stack, make sure your security firewall checks BOTH IPv4 and IPv6 traffic. Attackers can exploit unmonitored IPv6 connections.*
