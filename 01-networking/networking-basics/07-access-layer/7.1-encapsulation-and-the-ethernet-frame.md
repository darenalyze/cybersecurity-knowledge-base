# Encapsulation and the Ethernet Frame

## Ethernet Frame Basics

* **Ethernet:** Popular technology for local area networks (LAN).
* **Ethernet NIC:** Hardware card used by devices to connect to the network.
* **MAC Address:** Unique **hardware address** burned permanently into every NIC.
* **Scope:** Communication happens **NIC to NIC** on the **same network**.

> **Security Note:** MAC addresses can be spoofed (faked) using software. Never rely solely on MAC addresses for strong access control or user authentication.


## Ethernet Frame Fields

```
+----------+--------+-----------------+------------+-------------+--------------------+----------+
| PREAMBLE |  SFD   | DESTINATION MAC | SOURCE MAC | LENGTH/TYPE | DATA (PAYLOAD)     |   FCS    |
| (7 Bytes)|(1 Byte)|    (6 Bytes)    | (6 Bytes)  |  (2 Bytes)  | (46 - 1500 Bytes)  | (4 Bytes)|
+----------+--------+-----------------+------------+-------------+--------------------+----------+
```

* **Preamble (7 Bytes):** Synchronizes the receiving NIC with incoming timing bits.
* **Start Frame Delimiter / SFD (1 Byte):** Signals the start of actual frame data.
* **Destination MAC (6 Bytes):** Target device address on the local network.
* **Source MAC (6 Bytes):** Address of the sending device.
* **Length / Type (2 Bytes):**
  * **Length:** Size of the data payload.
  * **Type:** Identifies the upper protocol (e.g., IPv4 or IPv6).
* **Encapsulated Data (46–1500 Bytes):** The payload (e.g., IP packet, TCP, HTTP). Ethernet delivers it without modifying or checking its content.
* **Frame Check Sequence / FCS (4 Bytes):** Checks for data corruption during transmission.

> **Security Note:** Frame Check Sequence (FCS) only detects accidental transmission errors/noise—it does not protect against malicious tampering (Man-in-the-Middle attacks). Use cryptographic integrity checks (like HMACs) for security.

## Encapsulation

**Encapsulation** is wrapping network data inside a specific container (**frame**) so it can travel across a network.

### How It Works

* **Encapsulation (Sending):** Wrapping data inside a header/trailer.
* **De-encapsulation (Receiving):** Stripping away headers to extract the payload.
* **Frame:** Network container that acts like an envelope carrying address details.

```
+---------------------------------------------------------+
|                  ENVELOPE (Frame Header)                |
|  [ Destination MAC/IP ]  +  [ Source MAC/IP ]            |
|                                                         |
|    +-----------------------------------------------+    |
|    |               LETTER (Payload / Data)         |    |
|    +-----------------------------------------------+    |
+---------------------------------------------------------+
```

### Simple Analogy

| Physical Letter | Computer Network |
| :--- | :--- |
| **Letter Content** | Data / Message Payload |
| **Envelope** | Ethernet Frame / IP Packet |
| **Street Address** | MAC Address / IP Address |
| **Packing Letter** | **Encapsulation** |
| **Opening Letter** | **De-encapsulation** |

## IP Packet Structure (IPv6 Example)

Network packets require standardized fields to reach their destination across multiple networks.

```
+-------------------------------------------------------------+
|                     IPv6 Packet (40 Bytes)                  |
+-------------+-----------------+-----------------------------+
| Version     | Traffic Class   | Flow Label                  |
+-------------+-----------------+-----------------------------+
| Payload Length                | Next Header  | Hop Limit    |
+-------------------------------+--------------+--------------+
| Source IP Address                                           |
+-------------------------------------------------------------+
| Destination IP Address                                      |
+-------------------------------------------------------------+
```

* **Key Responsibility:** **IP (Internet Protocol)** routes messages across networks.
* **Crucial Fields:** **Source IP** (sender) and **Destination IP** (receiver).

> **Security Note:** Unencrypted IP packets reveal source and destination traffic patterns. Use VPNs or protocols like HTTPS/IPsec to protect packet privacy across untrusted networks.
