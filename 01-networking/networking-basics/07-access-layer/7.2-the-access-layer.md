# The Access Layer

## Ethernet Switches

### How Switches Work
* **OSI Layer:** Operates at **Layer 2 (Data Link Layer)**.
* **Forwarding Basis:** Uses **Layer 2 Ethernet Header** (MAC Addresses).
* **Core Tool:** Uses a **MAC Address Table** to direct traffic.

```
[Host 1: AAAA] ---> (Port Fa0/1) [SWITCH] (Port Fa0/4) ---> [Host 4: DDDD]
```

### Forwarding Process (Known Destination)
1. **Receive:** Switch gets frame on Port `Fa0/1` with Source `AAAA` & Destination `DDDD`.
2. **Lookup:** Checks MAC address table for destination `DDDD`.
3. **Forward:** Finds `DDDD` on Port `Fa0/4` $\rightarrow$ Sends frame **ONLY** out `Fa0/4`.


## MAC Address Tables

### How a Switch Learns (2-Step Logic)

```
                       INCOMING FRAME
              (Source: AAAA | Destination: DDDD)
                              │
                              ▼
                  ┌───────────────────────┐
                  │ 1. LEARN (Source MAC) │
                  └───────────┬───────────┘
                              │
            Is Source MAC in Table? ──YES──► Refresh 5-min timer
                              │
                             NO
                              │
                              ▼
                    Add MAC + Port to Table
                              │
                              ▼
               ┌────────────────────────────┐
               │ 2. FORWARD (Destination)   │
               └──────────────┬─────────────┘
                              │
          Is Destination MAC in Table? ──YES──► Forward to Specific Port
                              │
                             NO
                              │
                              ▼
                FLOOD / UNKNOWN UNICAST
              (Send out all ports except in)
```

#### Step 1: Learning (Source MAC)
* Examines the **Source MAC Address** of every incoming frame.
* If MAC is missing $\rightarrow$ Adds `Source MAC + Input Port` to table.
* **Aging Time:** Entries persist for **~5 minutes** before expiring.

#### Step 2: Forwarding (Destination MAC)
* Examines the **Destination MAC Address**.
* **Known Destination:** Forwards **only** to the matching port (filtering traffic).
* **Unknown Unicast:** Destination not in table $\rightarrow$ **Floods** frame out all ports *except* the receiving port.

### Host Behavior on Flooded Traffic
* **Non-matching hosts:** Drop/ignore the frame.
* **Target host:** Accepts frame and replies (which triggers Step 1 for the switch to learn its MAC).

> **Security Note:** *MAC Flooding Attacks exploit this behavior. An attacker floods the switch with fake MAC addresses to overflow the table, forcing the switch into "hub mode" (flooding all traffic) so the attacker can sniff sensitive data.*
