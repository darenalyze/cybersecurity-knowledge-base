# Broadcast Containment

## Video - The Ethernet Broadcast

**Ethernet Broadcast:** A message sent to **every device** on the local network.

* **Destination MAC:** `FF-FF-FF-FF-FF-FF` (all 1-bits in binary).
* **Switch Action:** **Floods** (sends) the frame out all ports except the incoming port.
* **Router Action:** **Blocks** the frame. Routers never forward broadcast traffic to other networks.

## Broadcast Domains

**Broadcast Domain:** A local network where all connected devices receive broadcast messages.

* **The Problem:** Too many devices = **excessive broadcast traffic** = slow network performance.
* **The Solution:** Use **routers** to divide one big network into multiple smaller broadcast domains.

## Video - Address Resolution Protocol

**ARP Purpose:** Find a device's unknown **MAC address** when you only know its **IPv4 address**.

### EXAMPLE: PC Finding an FTP Server
PC1 wants to send a packet to an FTP Server at `192.168.1.9`:

1. **Check Table:** PC1 looks inside its own **ARP table**.
2. **Send Request:** If missing, PC1 sends an **ARP Request** broadcast: *"Who has 192.168.1.9? Send me your MAC!"*
3. **Switch Floods:** Switch sends the request to all devices.
4. **Target Replies:** FTP Server sends back an **ARP Reply** with its MAC address directly to PC1.
5. **Send Data:** PC1 saves the MAC and sends the frame directly.

## ARP

ARP operates in **3 Simple Steps**:

1. **Request (Broadcast):** Sender asks the entire network for a MAC address.
2. **Reply (Unicast):** The matching target sends its MAC address directly back.
3. **Save (ARP Table):** Sender saves the IP-to-MAC mapping in its **ARP table** for future data sending.

Security Note: *Attackers can send fake ARP replies to steal network traffic (ARP Spoofing). Network switches use security features like Dynamic ARP Inspection (DAI) to stop this.*
